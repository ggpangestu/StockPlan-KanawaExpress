# Module Status

## Scope and evidence labels

This matrix records the implementation visible in the repository at the time of the audit. No application, database, browser, scheduler, build, export, or test execution was performed.

- `SOURCE_VERIFIED`: confirmed by reading the referenced repository files. It does **not** mean runtime-tested.
- `INFERRED_FROM_CODE`: a likely consequence of the inspected source, not an executed result.
- `VERIFIED_IMPLEMENTED`: the principal route/controller/model/view path is present in source.
- `PARTIALLY_IMPLEMENTED`: a usable source path exists, but an important part of the expected workflow is absent or disconnected.
- `SCAFFOLDED_ONLY`: a field, enum value, route surface, or display calculation exists without a complete workflow.
- `UNUSED`: present in source/schema/dependencies but no active application use was found.
- `NEEDS_RUNTIME_VERIFICATION`: source wiring exists, but its behavior has not been exercised.
- `UNKNOWN`: the repository alone does not establish the result or environment state.

Every runtime-status entry remains `NEEDS_RUNTIME_VERIFICATION` or `UNKNOWN`; source inspection is not reported as runtime evidence. "Present" tests below are source-verified test files whose execution result is unknown.

## Cross-cutting status summary

- `SOURCE_VERIFIED`: all classifications and gaps in this file are based on repository inspection.
- `NEEDS_RUNTIME_VERIFICATION`: every HTTP workflow, database mutation, browser interaction, scheduled command, export, upload, and test result.
- `UNKNOWN`: deployment configuration, applied migration state, database engine/isolation/foreign-key enforcement, scheduler availability, mail delivery, asset build state outside the inspected files, and live data.
- Nothing in this matrix is represented as runtime-tested.
